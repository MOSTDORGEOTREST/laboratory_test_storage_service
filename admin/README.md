# LTS Admin — панель управления лабораториями

Веб-админка («control plane»): создаёт изолированные инстансы LTS кнопкой.
Каждая лаборатория = отдельная база в общем Postgres-кластере + контейнер
`web` из общего образа + поддомен через Traefik + свой префикс в общем S3.

Реализация схемы из `feature/ADMIN_SERVER.md`.

## Возможности

- Создание лаборатории: live-проверка имени → база + роль в кластере →
  контейнер с метками Traefik → креды суперюзера показываются **один раз**.
- Стоп / старт, сброс пароля суперюзера (пересоздание контейнера с новым env).
- Мягкое удаление: контейнер снимается, база остаётся (grace-период).
- «Обновить все»: pull свежего образа и поочерёдное пересоздание контейнеров.
- Статусы в списке читаются из Docker (running / stopped / нет контейнера).

## Запуск

1. Один раз: wildcard-DNS `*.<DOMAIN>` → IP сервера.
2. Собрать образ основного приложения: `docker build -t lts:latest ./src`
3. `cp admin/.env.example admin/.env` и заполнить.
4. `docker compose -f admin/docker-compose.admin.yml --env-file admin/.env up -d --build`
5. Открыть `https://admin.<DOMAIN>` и создать первую лабораторию.

Локальная разработка без Docker/Postgres: `ADMIN_MOCK=1 uvicorn app:app --port 8100`
(логин/пароль admin/admin, операции имитируются, реестр в /tmp).

## Безопасность — прочитать обязательно

- Админ-контейнер держит `/var/run/docker.sock` — это **root на сервере**.
  Поддомен `admin.<DOMAIN>` закрыть VPN или IP-allowlist (пример middleware —
  в docker-compose.admin.yml, закомментирован).
- `MODE=prod` зашит в шаблон контейнера лаборатории и не настраивается:
  запуск основного приложения с `MODE=test` стирает базу (drop_all на старте).
- У каждой лабы свой `JWT_SECRET` — токены одной лабы не подходят к другой.
- Пароли суперюзеров хранятся в реестре (БД `lts_admin`) — доступ к кластеру
  и к серверу должен быть ограничен; при компрометации — «Сбросить пароль».
- Postgres и Redis не публикуют порты наружу (только docker-сеть).

## Данные и бэкапы

- Реестр лаб: база `lts_admin`, таблица `labs` (создаётся автоматически).
- Базы лабораторий: `lab_<имя>` в том же кластере; том `pgdata`.
- Удаление лабы НЕ удаляет базу. Физическая очистка вручную:
  `docker exec <postgres> pg_dump -U $PG_ADMIN_USER lab_geo > lab_geo.sql`
  затем `DROP DATABASE lab_geo; DROP ROLE lab_geo;`
- Бэкап всех баз по крону (пример):
  `docker exec <postgres> pg_dumpall -U $PG_ADMIN_USER | gzip > backup_$(date +%F).sql.gz`

## Ограничения текущей версии

- Один админ (логин/пароль из env), без ролей.
- Wildcard-TLS: в compose настроен HTTP-01 (сертификат на каждый поддомен
  выпускается при первом обращении). Для wildcard-сертификата переключите
  Traefik на DNS-01 своего DNS-провайдера.
- Боевой провижининг (Docker + Postgres) написан, но обкатан только код-ревью
  и синтакс-проверками; интерфейс и API прогнаны e2e в мок-режиме.
  Первую лабораторию создавайте на тестовом сервере.
